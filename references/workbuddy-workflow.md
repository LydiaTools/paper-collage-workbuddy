# WorkBuddy 完整制作流程

## 输入与项目

输入可以是一句选题、一份定稿文案或一条已认可的音轨。先确认已有内容，不擅改用户定稿。新建本期目录，所有路径相对 beats.json，不覆盖旧版。

1. **故事层**：读上游 beat-layer，围绕生活职场的具体处境安排问题、发展、转折与结果。选择合适叙事弧，不机械把每个主题都写成广告。镜头数量按实际故事与声音定，不固定三段。
2. **分镜层**：由 WorkBuddy 当前可用模型写 beats/shots，逐镜说明场景、景别、时长、运镜、物件动作与动作结果。用户已批准的文案逐字保留。已有音轨优先按真实时间安排画面。
3. **视觉层**：沿用用户已认可的橙绿奶油白；只有用户要求换风格时再探索。读上游 prompt-guide，使用不同物件、明确轮廓、纸边和阴影，稳定人物与材质。标题和字幕用后续文字层生成。
4. **准备资产**：运行 workflow.py plan 得到分镜表、素材提示词和动作计划。该命令没有调用图像模型；WorkBuddy 要另行使用实际图像工具或合法素材补齐部件。登记来源，不假称已生成。
5. **制作动画**：新故事创建 editable/index.html，逐镜按动作计划制作 HyperFrames 时间线。引用相对路径的 assets/gsap.min.js 和本期素材；根元素声明 width、height、fps=60、duration，并注册 window.__timelines.main。复用角色而非重复整图；对物件设起始状态和有限缓动，动作结束停稳。避免整张图推拉替代分层动作。
6. **配乐与口播**：默认本地生成与情绪适配的器乐，一条时间线贯穿全片。已认可口播直接加入 audio.narration。项目指定剪映音色时走原生流程，不拿别的服务替代。画面不足以容纳完整口播时，先延长镜头。
7. **实际渲染**：workflow.py render 严格检查 HTML，并渲染60fps画面，FFmpeg混音后输出成片。若运行失败，保留错误并修本环节；不以旧MP4冒充新运行，不交付 picture.mp4 中间件。
8. **交付与返修**：交付最终MP4、可编辑HTML、beats.json、素材、独立配乐、运行报告与本期制作步骤。复核文字、事件与动作、转场和声音；记录技术与主观验收的实际完成状态。

## 两条渲染路线

`focus-layered` 用于随包“忙乱→打断→专注”的已验证三段样片；`hyperframes` 用于助手按新故事实际创建的任意镜头数量工程。不能在第二条路线缺素材或HTML时退回第一条并只换标题。

正文、分镜与风格已认可时可继续制作，不为重复审核中断。新增付费外部生成服务或账号接入按用户选择执行，本 Skill 不会自动发起云端生成任务。
